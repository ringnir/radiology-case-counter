# 複数人で使う：Googleスプレッドシート＋Apps Script のセットアップ手順

科内・研修施設・同期など、**複数人の症例数をまとめて管理したい人（管理者）向け**の手順です。所要時間は20〜30分ほど。プログラミングの知識は要りません。メンバー側は、URLを開いて登録するだけです（Googleアカウントは不要）。

## 全体のしくみ

```
メンバーのブラウザ ──→ Apps Script の「ウェブアプリ」 ──→ データ用スプレッドシート
（スマホ・PC）          （管理者のGoogleアカウントで動く）     （管理者のドライブに自動で作られる）
        ↑ Googleサイトに埋め込んでも、URLを直接開いてもよい
```

- **管理者のGoogleアカウントで動きます**。メンバーはGoogleアカウント不要で、このアプリの「氏名＋パスコード」でログインします
- 症例のデータは、管理者のドライブにできるスプレッドシート1つに保存されます（サーバーを借りる必要はなく、無料のGoogleアカウントで動きます）
- 管理者は、全員の進捗を一覧で見たり、入学年度で絞り込んだり、メンバーの記録を開いて研修手帳の様式で出力したりできます。メンバー同士は、お互いの記録を見られません

## 用意するもの

| 用意するもの | 内容 |
|---|---|
| Googleアカウント | 管理者用。**長く使い続けられるもの**にしてください（異動・退職でなくなるアカウントだと、データごと失われます）。大学・病院の組織アカウントは、外部への公開が禁止されていて手順5で詰まることがあります。その場合は、個人のGoogleアカウントで作るか、組織の管理者に確認してください |
| パソコン | 設定作業用。スマホだけでは難しいです |
| **管理者パスコード** | 管理者がログインするための合言葉。**8文字以上**。あらかじめ決めておく |
| **招待コード** | メンバーが新規登録するときの合言葉。**6文字以上**。あらかじめ決めておく（メンバーにだけ伝える） |

2つのコードは、あとで `Code.gs` に書き込みます。管理者パスコードと招待コードは別の文字列にしてください。

## 手順0. ファイルを手元に用意する

1. このリポジトリのトップ（[github.com/ringnir/radiology-case-counter](https://github.com/ringnir/radiology-case-counter)）で、緑の **「Code」ボタン → 「Download ZIP」** を押す
2. ダウンロードした ZIP を解凍する
3. 中の `apps-script` フォルダにある次の2つを、メモ帳などのテキストエディタで開けるようにしておく
   - `Code.gs`
   - `Index.html`

（Gitに慣れている人は、リポジトリをクローンしても同じです。）

## 手順1. Apps Script のプロジェクトを作る

1. 管理者用のGoogleアカウントで、ブラウザから **<https://script.google.com>** を開く
2. 左上の **「新しいプロジェクト」** を押す（エディタが開く）
3. 左上の「無題のプロジェクト」をクリックして、わかりやすい名前（例：`専門医症例カウンター`）に変えて保存する

エディタには、最初から `Code.gs` というファイルがあり、中に `function myFunction() { }` と書いてあります。

## 手順2. Code.gs を貼り付けて、2つのコードを設定する

1. エディタの左にあるファイル一覧で **`Code.gs`** をクリックする
2. 中身を**すべて選択して削除**（Ctrl＋A → Delete。Macは ⌘＋A）
3. 手元の `apps-script/Code.gs` の中身を**すべてコピーして貼り付ける**
4. 先頭近くの、次の2行を探す

   ```js
   const ADMIN_PASSCODE = '';   // 管理者パスコード（8文字以上）
   const JOIN_CODE = '';        // 招待コード（メンバーが新規登録するときの合言葉・6文字以上）
   ```

5. 引用符 `' '` の**間に**、決めておいたコードを書く。例：

   ```js
   const ADMIN_PASSCODE = 'kanri-2026-xyz';
   const JOIN_CODE = 'nyugaku2026';
   ```

   - 引用符は消さない／全角にしない
   - 管理者パスコード8文字以上、招待コード6文字以上（足りないと「初期設定が終わっていません」と表示されます）
6. **保存**する（Ctrl＋S。Macは ⌘＋S、またはフロッピーのアイコン）

> **このコードを書き込んだ `Code.gs` は、GitHubなどに載せないでください。** コードは平文で書かれます。

## 手順3. Index.html を追加して貼り付ける

1. ファイル一覧の **「ファイルを追加」（＋のアイコン）→ 「HTML」** を選ぶ
2. ファイル名の入力欄に **`Index`** と入力して Enter（`.html` は付けない。大文字小文字もこのとおりに）
3. 自動で入っている内容をすべて削除し、手元の `apps-script/Index.html` の中身を**すべてコピーして貼り付ける**（約300KBあり、貼り付けに数秒かかります）
4. 保存する

これでファイル一覧に `Code.gs` と `Index.html` の2つが並びます。

## 手順4. setup を実行してデータ置き場を作る

1. エディタ上部の関数選択（「実行」ボタンの隣）を **`setup`** にする
2. **「実行」** を押す
3. 初回は **「承認が必要です」** と出るので、「権限を確認」を押す
   - 管理者用のGoogleアカウントを選ぶ
   - 「このアプリは Google で確認されていません」と出るが、**自分で作ったスクリプトなので問題ありません**。「詳細」→「（プロジェクト名）（安全ではないページ）に移動」を押す
   - 「スプレッドシートの表示、編集、作成、削除」の権限を求められるので「許可」する（データ用スプレッドシートを作るために必要です）
4. 下に表示される**実行ログ**に、次のように出れば成功です

   > 準備ができました。次はデプロイ（ウェブアプリ）に進んでください。データ保存先: https://docs.google.com/spreadsheets/d/…

   「先に、このファイル上部の ADMIN_PASSCODE と JOIN_CODE を書き換えてから…」と出たら、手順2の設定が足りていません。直して保存し、もう一度 `setup` を実行してください
5. Googleドライブの「マイドライブ」に、`専門医症例カウンター_データ（直接編集しないでください）` というスプレッドシートができています。これがデータの保存先です（`members` `docs` `config` の3シートが入っています）

`setup` は何度実行しても、すでにあるデータは消えません。

## 手順5. ウェブアプリとしてデプロイする

1. エディタ右上の **「デプロイ」→「新しいデプロイ」** を押す
2. 「種類を選択」の**歯車アイコン → 「ウェブアプリ」** を選ぶ
3. 次のように設定する

   | 項目 | 設定 |
   |---|---|
   | 説明 | 空欄でも、`初版` などでもよい |
   | 次のユーザーとして実行 | **自分（管理者のメールアドレス）** |
   | アクセスできるユーザー | **全員** |

   「全員」にするのは、メンバーがGoogleにログインしなくても使えるようにするためです。アプリ自体のログイン（氏名＋パスコード）があるので、パスコードなしでは中身は見られません
4. **「デプロイ」** を押す（承認を求められたら、手順4と同じ流れで許可）
5. 表示される **「ウェブアプリ」のURL**（`https://script.google.com/macros/s/…/exec`）を**コピーして保存**しておく

> URL は必ず末尾が **`/exec`** のものを使います。「デプロイをテスト」に出る `/dev` のURLは、自分しか開けないテスト用です。メンバーには渡さないでください。

## 手順6. 動作を確認する

1. コピーしたURLを、**新しいタブ**で開く（ログイン画面が出ればOK）
2. 上のタブで **「管理者」** を選び、管理者パスコードを入れてログイン → 「全員の進捗」（まだ0人）の画面になる
3. いったんログアウトし、**「新規登録」** で、テスト用の氏名・パスコード（6文字以上）・招待コードを入れて登録する
4. 症例を1件登録して、右上の表示が **「保存済み」** になることを確認する
5. もう一度ログアウトして、**「管理者」** でログイン → 一覧にテスト用のメンバーが出ていることを確認する
6. 「メンバー管理」でテスト用のメンバーを削除する（確認が2段階で出ます）

ここまでできれば、アプリとしては完成です。

## 手順7. Googleサイトに埋め込む（任意）

Googleサイトに載せなくても、手順5のURLをメンバーに伝えれば使えます。サイトにまとめたい場合の手順です。

1. <https://sites.google.com> でサイトを作る（または、既存のサイトを開く）
2. 右側のパネルの **「挿入」タブ → 「埋め込む」** を押す
3. **「URL」タブ**に、手順5のURL（`…/exec`）を貼り付けて「次へ」→「挿入」
4. 埋め込まれた枠の角をドラッグして、**大きく広げる**（横いっぱい、縦は画面いっぱい以上がおすすめ）
5. 右上の **「公開」** を押して公開する。**公開範囲（誰が見られるか）はGoogleサイト側の設定です。** メンバー以外に見せたくない場合は、サイトの共有設定で制限してください

**埋め込みのときの注意（ブラウザや設定によります）**

- ダウンロード（様式の出力・バックアップ）が動かないことがあります。その場合は、アプリの画面の一番下にある **「別のタブで開く」** のリンクから開き直して、そこで操作してください
- 同じく、ログイン状態や、読み込んだ様式がブラウザに残らず、**開くたびにログイン・様式の選び直し**になることがあります。この場合も、「別のタブで開く」から使うと改善します
- スマホでは、埋め込みではなく、URLを直接開くほうが使いやすいです

## メンバーへの案内

次の文面を、メールやチャットでメンバーに送ってください（【　】は書き換え）。

```
症例カウンターを使えるようにしました。

アドレス：【手順5のURL、または Googleサイトのアドレス】
初回は「新規登録」から、次の3つを入力して登録してください。
 ・氏名（管理者に表示されます。本名で）
 ・パスコード（6文字以上。自分で決めて、忘れないように）
 ・招待コード：【　　　　】

登録したあとは、「ログイン」から氏名とパスコードで入れます（スマホ・PCどちらも同じ）。
症例を登録するときは、患者ID・患者氏名・生年月日は入れないでください。
診断名などの自由記述にも、個人が特定できる内容は書かないでください。
「設定」で入学年度と受験予定日を入れておくと、残り日数が出ます。
パスコードを忘れたときは、管理者に連絡してください。
```

招待コードは、**メンバーになる人にだけ**伝えてください（掲示板などに載せない）。

## 運用

### 管理者の画面

ログイン画面の **「管理者」** タブに、管理者パスコードを入れると入れます。メンバーとして登録している人は、メンバー画面の **「管理者として入る」** から、管理者パスコードを入れて切り替えることもできます（メンバー画面にも戻れます）。

| 画面 | できること |
|---|---|
| 全員の進捗 | 全員の進捗（3つの専門医）、入学年度、受験予定日、残り日数、不足件数、週あたりのペースの一覧。**入学年度で絞り込み**、並べ替え、氏名の検索ができる。氏名を押すと、そのメンバーの記録を**閲覧のみ**で開き、研修手帳の様式・Excel・CSVで出力できる |
| メンバー管理 | 氏名の変更、**パスコードの再設定**、メンバーの削除（2段階の確認。記録も消える） |
| 全員出力 | 全員分をExcel（集計＋症例一覧）・CSVで保存。「スプレッドシートに書き出す」を押すと、データ用スプレッドシートに `全員サマリ` `全員症例一覧` のシートができて、そのURLが開ける（確認・印刷用） |

管理者が他のメンバーの記録を書き換えることはできません（閲覧のみ）。

### メンバーの追加・削除・パスコードの再設定

- **追加**：招待コードを伝えて、本人に「新規登録」してもらう（管理者が代わりに登録する機能はありません）
- **パスコードを忘れたとき**：管理者画面の「メンバー管理」で、そのメンバーのパスコードを再設定して、新しいパスコードを本人に伝える。メンバー本人は、ログイン後の「設定」でパスコードを変えられます
- **氏名の表記を直したいとき**：「メンバー管理」で氏名を変更する（同じ氏名は登録できません。全角・半角、スペースの有無、大文字小文字の違いは同じ氏名として扱います）
- **卒業・退会**：必要なら先に「全員出力」で保存してから、「メンバー管理」で削除する

### 毎年の使い回し

データを消さずに、そのまま使い続けられます。

1. 新しい年度の人に、招待コードを案内して登録してもらう
2. 各自に、「設定」で**入学年度**と**受験予定日**を入れてもらう
3. 管理者画面の「全員の進捗」で、**入学年度で絞り込んで**見る

招待コードを年度ごとに変えたいときは、`Code.gs` の `JOIN_CODE` を書き換えて、[新しい版に更新するとき](#新しい版に更新するとき)の手順4（新バージョンのデプロイ）をします。すでに登録済みのメンバーには影響しません。

### バックアップ

- **データ用スプレッドシートのコピー**：ドライブでスプレッドシートを開き、「ファイル → コピーを作成」で、ときどき（月1回など）コピーを残す。「ファイル → 変更履歴」でも、以前の状態を見られます
- **各自のバックアップ**：メンバーには、「出力・バックアップ」タブの「バックアップを保存」（JSON）を、ときどき保存してもらう
- **データ用スプレッドシートを消さない・中身を直接書き換えない**。誤って削除すると、`setup` を実行したときに空のスプレッドシートが新しく作られ、以前のデータにはつながらなくなります（ゴミ箱に残っている間なら戻せます）

## 新しい版に更新するとき

アプリが新しくなったときの手順です。**URLは変わりません。** 変わったファイルだけ差し替えます（どちらが変わったか分からなければ、両方を差し替えます）。

1. 新しい ZIP をダウンロードして解凍する（手順0）
2. エディタで、変わったファイルの中身を、**すべて新しい内容に置き換える**
   - `Index.html` ：画面の変更。これだけ差し替えれば足りることがほとんどです
   - `Code.gs` ：サーバー側の変更。**置き換えると、先頭の2つのコードが空に戻ります。** 管理者パスコードと招待コードを、**もとと同じものに書き直して**から保存してください（別のものにしたい場合を除く）。書き直さずにデプロイすると、「初期設定が終わっていません」と表示されます
3. `Code.gs` を差し替えた場合は、関数 `setup` をもう一度実行する
4. **「デプロイ」→「デプロイを管理」→ 鉛筆アイコン → バージョンを「新バージョン」→「デプロイ」** を押す（**保存しただけでは、メンバーが使っているURLには反映されません**）

2つのコードは、あなた自身が分かる場所（パスワード管理ツールなど）にも控えておくと、更新のときに楽です。

## 安全面と制限

### 誰が何を見られるか

| 誰が | 見られるもの |
|---|---|
| メンバー本人 | 自分の記録だけ |
| 管理者（管理者パスコードを知っている人） | 全員の記録（閲覧のみ） |
| **スクリプトの持ち主（管理者のGoogleアカウント）** | **すべて。** データ用スプレッドシートを直接開けば、全員の症例が読めます。`Code.gs` には2つのコードが平文で書いてあります |

- **データ用スプレッドシートを、他の人に共有しないでください**（共有すると、全員分の症例が読めてしまいます）。`Code.gs`（スクリプト）の編集権限も、渡さないでください
- メンバーのパスコードは、塩（ソルト）つきのSHA-256のハッシュでシートに保存され、管理者にも元のパスコードは分かりません（管理者にできるのは「再設定」だけ）
- URL を知っていれば、誰でもログイン画面は開けます。中に入るには、招待コード（新規登録）か、氏名とパスコード（ログイン）が必要です。ログイン（氏名ごと）・招待コード・管理者パスコードは、それぞれ5回続けて間違えると、15分ほど入力できなくなります
- ログイン状態は30日続きます

### 患者さんの情報について

このアプリは、患者ID・患者氏名・生年月日の入力欄を持たず、レポート一覧の取り込みでもそれらの列を読みません。それでも、年齢・性別・検査日・診断名などの組み合わせは、状況によっては個人が推定されることがあります。**症例の情報を院外のクラウドに置くこと自体が、所属施設の規程で制限されている場合があります。** 使い始める前に、所属施設の情報セキュリティ・倫理の担当に確認してください。

### 上限・目安

- 数十人規模を想定しています
- 登録できるメンバーは500人まで
- 1人・1か月あたり、約64万文字（数千件）まで保存できます
- 同時に保存する人が多いと、「混み合っています」と出ることがあります（少し待って、もう一度）

## 困ったとき

| 症状・表示 | 原因と対処 |
|---|---|
| 「管理者の初期設定（管理者パスコードと招待コードの設定）がまだ終わっていません。」 | `Code.gs` の2つのコードが空、または短い（管理者パスコード8文字以上、招待コード6文字以上）。直して保存し、**新バージョンでデプロイ**する（手順5、または更新手順の4） |
| 「管理者の初期設定（setup の実行）がまだ終わっていません。」 | `setup` を実行していない。手順4をやる |
| コードを直したのに、画面が変わらない | `/exec` のURLは、デプロイした時点の版を動かします。**「デプロイを管理」で新バージョンにする**（更新手順の4） |
| 承認画面で「このアプリは Google で確認されていません」 | 自分で作ったスクリプトなので正常です。「詳細」→「（プロジェクト名）（安全ではないページ）に移動」 |
| 「招待コードが違います。」 | メンバーが入力した招待コードが、`Code.gs` の `JOIN_CODE` と違う。前後の空白に注意 |
| 「失敗が続いたため、15分ほど入力できません。」 | 5回続けて間違えたため。15分待てば自動で解除されます（氏名ごと・招待コード・管理者パスコードで、それぞれ数えます） |
| 「その氏名はすでに登録されています。」 | 同じ氏名（全角半角・スペース・大文字小文字の違いは同じ）がすでにある。ログインするか、表記を変える |
| 「混み合っています。少し待ってから…」 | 同時に使っている人が多い。少し待って、もう一度 |
| 「データが大きすぎて保存できません。」 | 1人・1か月あたりの上限（約64万文字）を超えた。ふつうは起きません。件数を2以上にした「件数だけの記録」にまとめるなどして減らす |
| Googleサイトで、真っ白・拒否された | URLが `/exec` か、「アクセスできるユーザー」が「全員」になっているか確認（手順5）。**組織のGoogleアカウントでは、外部への公開が制限されていることがあります** |
| ダウンロードできない／毎回ログインや様式の選び直しが必要 | 埋め込み画面では、ブラウザの制限で起きることがある。画面の一番下の **「別のタブで開く」** から使う |
| メンバーがパスコードを忘れた | 管理者画面の「メンバー管理」で再設定する |
| 管理者パスコード・招待コードを忘れた | `Code.gs` の先頭に書いてあるので、エディタで確認する |
| 管理者パスコードを変えたい／全員を強制ログアウトしたい | 管理者パスコードは `Code.gs` を書き換えて、新バージョンでデプロイ。ただし、**すでにログインしている人（管理者含む）は最長30日そのまま入れます。** すぐにログアウトさせたい場合は、エディタ左の「プロジェクトの設定」（歯車）→ 下の「スクリプト プロパティ」で **`SECRET` を削除**し、関数 `setup` を実行する（新しい `SECRET` ができ、全員がログインし直しになります。データは消えません） |
| 症例が消えた、おかしい | まず、データ用スプレッドシートの「ファイル → 変更履歴」で以前の状態を探す。メンバーが保存していたバックアップ（JSON）からも、アプリの「バックアップから復元」で戻せる |

## 学会の様式の扱い

- `apps-script/Index.html` には、**学会の様式ファイルは含まれていません。** 様式への書き込み出力を使う人は、アプリの「出力・バックアップ」タブで、様式のExcel（.xlsx）を選びます（一度選ぶとブラウザに保存されます。埋め込み画面などでは保存されず、そのつど選び直しになることがあります）
- 管理者がメンバーの記録を開いたときも、様式の出力には、管理者のブラウザで様式を選ぶ必要があります（画面上部に選択欄が出ます）
- **様式を内蔵した版を作ってApps Scriptで配ることは、おすすめしません。** 内蔵版の `Index.html` は、ログインする前でも、URLを知っている人なら誰でも様式を取り出せてしまいます。学会の様式の取り扱い条件に注意してください。作り方は、リポジトリのトップの README（「様式を内蔵した私用版」）にあります
